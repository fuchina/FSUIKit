## FSToast 宽度改为内容自适应

`FSKit/FSKit/Classes/FSToastCenter.swift` 的 `FSToastOverlay`。

病根：`frame(maxWidth: WIDTHFC - 50)` 挂在 `Text` 上（`background` 内侧）。`Text` 收到被夹到
上限的提议后，`frame` 自身就撑满 343pt，`background` 自然也是一整条 —— 短文案同样显示成固定宽的大长块。

改法：把宽度上限**挪到 `background` / `clipShape` 之外**，顺序变成
`Text → font → padding(.horizontal,10) → frame(minHeight:40) → fixedSize(horizontal:false, vertical:true)
 → background → clipShape → frame(maxWidth: maxWidth) → allowsHitTesting(false)`。
`Text` 在有限提议下是 tight-fit，短文案按内容宽，超长才吃满上限并居中换行。
抽出 `private var maxWidth: CGFloat { WIDTHFC - 50 }`（值不变）。未加最小宽度。

验证：`swiftc -typecheck`（桩 `WIDTHFC`，exit 0）+ 在 macOS 用 `ImageRenderer` 把改前/改后
5 组文案渲染成 PNG 对比（`/tmp/toastlayout/`），确认短文案贴内容宽、长文案换行且不超宽。
**未跑 xcodebuild。**

### 返工：切换输入框时面板会上下跳

用户反馈：输入框模式下切换输入行，弹窗会移动位置。要求「初始定好位置后就不许动」。

病根：原实现是「让系统避让 + 自己补偿 `keyboardShift += delta/2`」。
切换输入框时键盘高度变（数字键盘 ↔ 全键盘），系统会**重新按新键盘居中**；而
`baseKeyboardHeight` 在键盘收起那一瞬间会被重置成 0，补偿基准跟着丢 ⇒ 面板跳到新位置。
累加式 `+=` 遇到多次小幅变化还会漂移。

改成「位置自己定、算一次锁死」：
1. `ZStack` 加 **`.ignoresSafeArea(.keyboard)`** —— 彻底关掉系统避让，面板不再随键盘重排。
2. 键盘**第一次**弹出时算一次 `keyboardLift = -(键盘高 - 底部安全区) / 2`，`liftDone` 锁死，
   之后键盘变高变矮、切几个输入框都不再动；键盘收起也不回弹。
3. 面板用 `.offset(y: keyboardLift)`，删掉 `panel` 里的 `.offset(y: keyboardShift)`。

这个公式是实测反推的：键盘 308 / safeBottom 34 → 137，系统自己避让也是 137
（面板 319.58→182.58）。代入后 `maxY 582.42 - 137 = 445.42`，系统避让后实测 `445.41`，
**精确等价**。因为数字键盘比全键盘矮，按第一次（无论哪种）算出来的位置都不会被更高的键盘挡住。

验证：`swiftc -typecheck` 通过 + FSKit `xcodebuild` **BUILD SUCCEEDED**。
⚠️ **没在真实 App 里跑过**：探针里 `@FocusState` 切到 `.numberPad` 那一步会让 App 挂掉
（`panel.txt` 只写到「--- focus 0 ---」就断），换 addSubview 又弹不出键盘，所以「切换输入框不动」
这条只做了数值等价推导，没做端到端复现。

### 入场动画"没劲道" + 退场键盘拖到下一页

用户反馈两条：①入场没弹性、只是平移；②消失时键盘退出慢，会出现在别的页面。

**① 病根不是 spring 参数，是键盘上移把入场吃掉了。**
输入弹窗入场时同时发生两件事：`transition(.opacity)` 的淡入 + `keyboardLift` 的 137pt 上移。
后者用的是 `.easeOut(duration: 0.2+)`（均速收尾），137pt 的大幅位移直接盖过了淡入 ⇒ 观感=纯平移。
另外原来 `.animation(.interpolatingSpring(522.35, 45.71), value:)` 挂在 `FSAlertHost` 的 ZStack 上，
**它的优先级高于外部事务**，所以 show/dismiss 想用不同曲线是做不到的。

改法：
- 曲线挪到 `FSAlertCenter.presentAnimation` / `dismissAnimation` 两个静态常量，在 `show()` / `dismiss()`
  里用 `withAnimation(...)` 驱动；`FSAlertHost` 上那句 `.animation(_:value:)` **必须删掉**。
- 入场：`interpolatingSpring(stiffness: 700, damping: 34)`（ζ≈0.64，约 7% 过冲，落定 ≈0.24s）。
  系统实测是 ζ=1.0 临界阻尼（不反弹），这里**故意偏离**系统按用户要求加弹性。
- 面板自身再 `.scaleEffect(0.92 + 0.08 * entrance)`，`entrance` 由 `onAppear` + `withAnimation` 推。
  ⚠️ 缩放**不能挂在 transition 上**：那会把全屏遮罩一起缩放，边缘露底。
- `keyboardLift` 的曲线也换成 `interpolatingSpring(stiffness: 560, damping: 38)`，否则还是纯平移。
- 退场：单独的 `.easeOut(duration: 0.18)`，比入场快，不再拖尾巴。

**② 键盘拖到下一页**
原实现只把 `current = nil`，视图被移除后 UIKit 才去 resign 第一响应者，键盘收起动画晚一个节拍启动。
改法：`dismiss()` 里**先** `UIApplication.shared.sendAction(#selector(UIResponder.resignFirstResponder), ...)`
（仅当 `current?.inputs.isEmpty == false` 时才发，避免误收别处的键盘），**再** `withAnimation(dismissAnimation) { current = nil }`。

验证：FSKit `xcodebuild` **BUILD SUCCEEDED**。动画手感只能由用户在真机判，截图无法验证。

## FSToast 宽度改为内容自适应

`FSKit/FSKit/Classes/FSToastCenter.swift` 的 `FSToastOverlay`。

病根：`frame(maxWidth: WIDTHFC - 50)` 挂在 `Text` 上（`background` 内侧）。`Text` 收到被夹到
上限的提议后，`frame` 自身就撑满 343pt，`background` 自然也是一整条 —— 短文案同样显示成固定宽的大长块。

改法：把宽度上限**挪到 `background` / `clipShape` 之外**，顺序变成
`Text → font → padding(.horizontal,10) → frame(minHeight:40) → fixedSize(horizontal:false, vertical:true)
 → background → clipShape → frame(maxWidth: maxWidth) → allowsHitTesting(false)`。
`Text` 在有限提议下是 tight-fit，短文案按内容宽，超长才吃满上限并居中换行。
抽出 `private var maxWidth: CGFloat { WIDTHFC - 50 }`（值不变）。未加最小宽度。

验证：`swiftc -typecheck`（桩 `WIDTHFC`，exit 0）+ 在 macOS 用 `ImageRenderer` 把改前/改后
5 组文案渲染成 PNG 对比（`/tmp/toastlayout/`），确认短文案贴内容宽、长文案换行且不超宽。
**未跑 xcodebuild。**

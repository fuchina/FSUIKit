## `showAlertWithMessage` / `showAlertWithTitle` 的 handler 改为可选

`FSUIKit/Classes/Swift/FSUIKit.swift`：
- `showAlertWithMessage(_:handler:)` → `handler: ((UIAlertAction) -> Void)? = nil`
- `showAlertWithTitle(title:message:ok:handler:)` → 同样加 `= nil`

调用方可直接 `FSUIKit.showAlertWithMessage("xxx")`，不必再传 `handler: nil`；
既有传 nil 的调用点（`FSShare.swift` 153/186/223 三处）二进制/源码兼容，一行未动。

注：可选闭包作最后一个参数，trailing closure 写法也合法：
`FSUIKit.showAlertWithMessage("xxx") { _ in }`。

## 第四轮：`FSAlertInputConfig` 里最后的 UIKit 类型

- `FSAlertKeyboard`（FSKit 新增，6 个 case）替代 `UIKeyboardType`：**只是不外泄，内核仍是 UIKit**
  —— SwiftUI 的 `.keyboardType()` 就吃 `UIKeyboardType`，没有替代品。
- `autocapitalization: TextInputAutocapitalization?` 替代 `UITextAutocapitalizationType`：真 SwiftUI 类型。
- `showsClearButton: Bool` 替代 `UITextField.ViewMode`：自绘本就只有「有内容显示 xmark」这一个语义。
- `alert(controller: UIViewController?)` → `AnyObject?`：该参数早已无用。
- `UIDevice` 保留（iPad 判断无 SwiftUI 等价物，`UITraitCollection.current` 在静态方法里不可靠）。

调用点 26 处替换 / 12 文件。`FSAlertKeyboard` 同名 case 让 35 处 `cfg.keyboardType = .xxx` 零改动。

校验：FSKit `-emit-module` 通过；FSUIKit 三文件 + 三套 harness `-typecheck` 通过。

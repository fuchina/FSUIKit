# 2026-10-10

## FSNavigationController 编译报错修复

- 报错：`Cannot use optional chaining on non-optional value of type '() -> Bool'`
- 位置：`FSUIKit/Classes/Swift/FSBaseController/FSNavigationController.swift:26`
- 原因：`FSNavigationControllerPopDelegate` 里 `navigationShouldPopOnBackButton() -> Bool` 是**必选（非 optional）** 方法，但调用处写了 `topController.navigationShouldPopOnBackButton?() ?? true`，对非可选值用了可选链。协议没有 `@objc`，所以方法本来就不可能是 optional。
- 修法（最小改动）：`canPop = topController.navigationShouldPopOnBackButton()`，去掉 `?()` 和 `?? true`。
- 行为无变化：该分支只在 `topViewController as? FSNavigationControllerPopDelegate` 成功时进入，此时方法必定存在，`?? true` 永远是死代码。
- 依赖关系确认：全工程只有 `FSTextViewController`（第 10 行声明遵从，第 82 行 `@objc public func` 实现）实现该协议，已成为必选实现，故不会引发新的编译错误。
- 备选方案（未采用）：若要保持 Objective-C 的可选方法语义，需把协议改成 `@objc public protocol` + `@objc optional func`，此时原可选链写法才合法。当前无此需求。

## 追加：F 要求改为「可选方法」（最终采用方案）

F 明确选择保留 ObjC 可选方法语义，故改回：

```swift
@objc public protocol FSNavigationControllerPopDelegate: AnyObject {
    @objc optional func navigationShouldPopOnBackButton() -> Bool
}
```

调用处恢复为 `canPop = topController.navigationShouldPopOnBackButton?() ?? true`（此时 `?()` 合法，返回 `Bool?`）。

验证：`xcrun swiftc -typecheck -sdk <iphoneos sdk> -target arm64-apple-ios18.0 FSNavigationController.swift` → exit 0（该文件自包含，可单文件 typecheck）。
FSTextViewController 无法单文件 typecheck，因为 `FSBaseController.swift` 依赖 `FSKit`，本仓库内无该 Pod（Pods 目录里只有 FSCalculator/FSWindow/MJRefresh，缺 FSKit，Pods 可能已过期）。

附带收益：协议变 `@objc` 后 ObjC 类也能遵从。风险点已核对——全工程仅 FSTextViewController 遵从，其实现写法 `@objc public func ...() -> Bool` 正好匹配 `@objc optional` 需求，conformance 依然成立。

## @objc 全量盘点（评估「能否全部去掉」）

- 组件本体 `FSUIKit/Classes` 已 **100% Swift**，无任何 `.h/.m`（`FSUIKitSample` 里的 ObjC 是历史残留，它 import 的 `FSUIKit.h` / `FSImage.h` / `UIView+ModalAnimation.h` 在仓库里都不存在，已编不起来）。
- 全组件共 **20 处 `@objc`，分布在 17 个文件**：17 个方法 + 协议 1 处 + `@objc optional` 方法 1 处 + 协议实现 1 处。
- 结论：**不能全去掉**。19 处是 ObjC 运行时回调入口（16 处 selector 回调：UITapGestureRecognizer / UIButton addTarget / NotificationCenter selector 版；1 处 CADisplayLink selector；2 处 `@objc optional` 协议前提），删掉 `#selector` 直接编译失败、或运行时静默不回调。仅 `FSTextViewController.swift:82` 可删，但编译器会按协议要求自动推断成 `@objc`，等于没删。
- 两条硬证据（本机 `swiftc` 实测）：
  1. `#selector` 指向未标 `@objc` 的方法 → `error: argument of '#selector' refers to instance method 'noObjc()' that is not exposed to Objective-C`。
  2. 实现 `@objc optional` 协议要求时**省略** `@objc`，`f?()` 可选派发与 `responds(to:)` 运行时均为 `true` ⇒ Swift 会自动推断 `@objc`。
- 唯一「结构性无法归零」的点是 `FSRoundVanView` 的 `CADisplayLink(target:selector:)`（无闭包 API）；其余都可用 `UIAction` / 闭包版 NotificationCenter / 普通协议+默认实现 换掉，但需为 13 处手势新增闭包包装类（`@objc` 只是从 13 处收敛成 1 处，不是清零），且无性能收益（`@objc` 仅走 `objc_msgSend`，与 Swift 动态派发同量级）。**建议维持现状。**

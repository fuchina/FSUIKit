## UIAlertController 回退可行性实测（iPhone 17 Pro / iOS 26.5 + iPhone 16 Pro / iOS 18.5）

起因：用户认为 FSUIKit 的 `alert` / `alertInput` 自绘版与原生差距太远，问能否改用原生 + 点空白区 dismiss。

### 实测结论（探针 `/tmp/FSAlertProbe{,2,3}`，纯 UIKit，swiftc 直编 .app + simctl 安装运行）

**视图层级（两个系统版本完全一致）**

```
UIWindow
└─ UITransitionView                      ← presentationController.containerView，全屏、可交互
   ├─ UIView  bg=black@0.20              ← 遮罩 / dimming view（系统绘制，非 alert.view）
   ├─ UIView（键盘占位，输入模式有）
   ├─ _UIKeyboardLayoutAlignmentView（高度 = 键盘高 308）
   └─ _UIAlertControllerPhoneTVMacView   ← 就是 alert.view 本身，**frame == 面板矩形**
```

- `alert.view.frame` 就是面板矩形，不是全屏。`bounds` 与 `frame` 尺寸相同。
  - iOS 26.5：两按钮 **320 × 172**；输入框 **320 × 264**；四按钮 **320 × 320**；圆角 34。
  - iOS 18.5：两按钮 **270 × 141**；输入框 **270 × 198**；四按钮 **270 × 257**。
  - ⚠️ **自绘代码里硬编码的 320 宽 / 34 圆角是按 iOS 26 采样的，在 iOS 18 设备上就是错的** ——
    这是「和原生差距太远」的一条硬证据（270 vs 320、圆角约 14 vs 34）。
- `modalPresentationStyle = 4 (.overFullScreen)`，两版一致。
- alert.view 的 `window` 就是主 window（不是新建 window），层级在 `rootViewController.view` **之上**
  ⇒ SwiftUI 的 toast / loading overlay 会被 alert 遮罩盖住。

**点外关闭的判据（可行，且不需要私有类名）**

- ❌ 手势挂 `alert.view`：点面板外 `alert.view.hitTest` 直接返回 `nil`（点在 bounds 外），收不到事件。
- ✅ 手势挂 `presentationController.containerView`（全屏）。
- 判定用 delegate：`!touch.view.isDescendant(of: alert.view)` → 接收，否则拒绝。
  完全免疫几何 / transform / 动画，也不依赖私有类名。
- 点外部时 `window.hitTest` 返回的是那个 `bg=black@0.20` 的 UIView（`UIView < UITransitionView < UIWindow`）。
- `cancelsTouchesInView = false` 保证按钮点击不受影响。

**present 串行（这是唯一真风险）**

- alert 仍在显示时 present 第二条：**静默失败**，completion 不回调，`a2.view.window == nil`，无 warning。
- 在 dismiss completion 里 present：✅ 成功。
- `dismiss(animated:true)` 后**不等** completion 立刻 present：本次也成功（`presentedViewController` 已变 nil，
  UIKit 自己排队），但不可依赖。
- ⇒ 实现必须做 pending 队列，在 dismiss completion 里 flush。

**其他**

- `alert.textFields` 预填 `$0.text = "88.00"` 生效，键盘自动弹起，`firstResponder = _UIAlertControllerTextField`。
- 输入框 frame 高 35（iOS 26）/ 17（iOS 18，实际点击区域更大）。
- `present` 失败时 `a.view` 未布局，frame 停在全屏 —— 一度让我误判「alert.view 是全屏」，实际是 present 没成功。

### 实施（已完成）

1. `FSKit/Classes/FSAlertCenter.swift`：`alert` 后端换成 `UIAlertController`
   - 队列：`pending` + `activeAlert` + 50ms 重试（上限 5s），`dismiss`/按钮 handler 后 `pump`；
   - 点外关闭：手势挂 `presentationController.containerView`，`FSAlertTapOutside` 用
     `!touch.view.isDescendant(of: alert.view)` 判定；`tapOutsideToDismiss` 是**总开关**（与自绘版一致）；
   - `FSAlertDialog` / `FSAlertButtonStyle` 保留但不再被引用（用户要求「代码功能保留」）；
   - `FSAlertHost` 只剩 actionSheet 的 `confirmationDialog`；
   - `current` 在 alert 时只作状态标记（`.fsAlert` 靠它的 id 同步 `isPresented`）。
2. `FSUIKit/Classes/Swift/FSUIKit.swift`：6 处入口标 `@available(*, unavailable, ...)`：
   `alert` ×2 / `alertInput` / `showAlertWithMessage` / `showAlertWithTitle` / `.fsAlert`。
   `showAlertWithMessage` 改为调 internal `showAlert(title:message:ok:handler:)`，避开 unavailable 自调用。
3. 探针 `/tmp/FSAlertProbe4` 直接编译 `FSAlertCenter.swift` 验证：
   连续 3 条 S1→S2→S3 依次上台不丢；无按钮 alert 能显示能关；输入框预填 88.00、键盘自动弹、firstResponder=true；
   containerView 上确实挂到 1 个 tap（delegate = FSAlertTapOutside，cancelsTouchesInView = false）。
4. `swiftc -typecheck`（三文件同 module + 去掉 `import FSKit`）通过；
   加一个 consumer 调用点验证：报 `'alert(...)' is unavailable: 弹窗能力已由系统 UIAlertController 承接…`。
